# iOS App 5 语言翻译风格指南

翻译每条文案前都要扫一眼对应语言的小节。**目标**：翻译看起来像该语言原生 App，不是机翻味、不是直译、不踩文化雷区。

## 通用原则（所有语言）

### 1. 区分文案类型，决定语气和结构

| 类型 | 中文示例 | 风格特征 |
| --- | --- | --- |
| 按钮 / 短动作 | 删除、取消、全选 | 简短、祈使/动名词，1-3 词最佳 |
| 导航栏标题 | 整理相册、相簿 | 名词短语、首字母大写规则按各语言惯例 |
| 段落说明 | 当前相册中没有照片 | 完整句、自然、对用户友好 |
| 错误 / 弹窗标题 | 删除失败、确认删除 | 简洁、客观、不带感情色彩 |
| 提示 / 引导文案 | 整理你的相册 | 鼓励性、自然口语化 |
| 数量描述 | %lld 张照片已标记 | 自然 + 占位符位置合适 |

判定方式：看 key 的语义和上下文。`*.title` `*.navigation_title` 一般是导航/标题；`*.subtitle` `*.description` 是说明；`*.button` `*.action` 是按钮；`*_format` 是参数化文案。

### 2. 占位符的位置

各语言语序不同，占位符位置要符合该语言自然语序。例子：

- 中文：`找到 %d 个空相簿`
- 英文：`Found %d empty albums`
- 日文：`%d件の空のアルバムが見つかりました`
- 韩文：`빈 앨범 %d개를 찾았습니다`

可以看出韩文/日文里数量+量词放在名词后或中间。**不要照搬中文位置硬怼**。

### 3. 长度控制

- 按钮文案：尽量 ≤ 8 字符（中日韩）或 ≤ 15 字符（拉丁字母）
- 标题：尽量 ≤ 15 字符
- 弹窗按钮：必须短（确认/取消/继续 这种）
- 段落说明：可以放开一点，但别加源里没有的修饰

准确性 > 长度。但能短不长。

### 4. 不要加源里没有的信息

源说「删除选中」，译文就是「删除选中」对应物，不要变成「请删除已选中的项目」。**App 文案讲究干净，加字 = 噪音**。

## en (English)

### 大小写

- **按钮 / 导航标题**：Title Case（每个实词首字母大写）—— `Delete Selected`、`Clean Empty Albums`、`Confirm Exit`
- **完整句子**：Sentence case（只有句首大写，专有名词除外）—— `All your albums contain photos`、`Are you sure you want to exit?`
- **短提示 / 状态**：Sentence case —— `Scanning empty albums...`、`Loading library data...`

### 标点

- 句末**句号必加**（完整句子）。短按钮文案**不加句号**。
- 省略号用 `...`（3 个英文点），不要用 Unicode `…`，本项目已有惯例。
- 问号、感叹号用英文标点。

### 风格雷区

- 不要用 `you` 之外的称谓变体（不要 `the user`、不要 `one`）。
- 不要用法律式被动语态 `The selected items will be deleted`，要主动 `Delete selected items`。
- 不要随便加 `Please`，App 文案里通常不需要。例外：弹窗 / 引导用户授权时可加。
- 缩写慎用：`Delete` 不写成 `Del`，`Settings` 不写成 `Set`。

### 复数

英语**必须**写 `one + other`，且文案不同：

- `one`：`%lld photo selected`（单数 photo，无 s）
- `other`：`%lld photos selected`（复数 photos）

注意：英语 `one` 只在数量 = 1 时显示。**不要**把 `one` 也写成复数形式偷懒。

## zh-Hans（简体中文）

如果基准就是 zh-Hans，跳过这一节（除非用户基准是其他语言要翻成中文）。

### 风格

- 简洁、自然、口语化（不要书面正式）。
- 按钮用动词（短）：删除、取消、确认、继续、完成。
- 说明用完整句子但不要太长。
- 不要"您"，用"你"。App 文案现代风格都是"你"，"您"显得过度正式。**例外**：法务/隐私/付费协议这种正式场景可以"您"。

### 标点

- 句末**不加句号**（按钮、标题、列表项）。
- 完整说明句末**也通常不加句号**（看现有 xcstrings 文件，绝大多数没有句号）。例外：弹窗 message 多个句子时，中间用句号断开。
- 用中文标点（，。？！）和占位符之间留空格：`找到 %d 个空相簿` —— `%d` 前后都有空格。
- 省略号用 `...`（3 个英文点），和英文保持一致。

### 复数

只写 `other` 一条，文案里直接用 `%lld 张`、`%lld 个`、`%lld 项` 这种「数字 + 量词」结构。中文不区分单复数。

## zh-Hant（繁体中文，台湾/香港用语）

**从 zh-Hans 翻译过来**而不是从零翻译，速度快、术语统一。但**不只是繁体字转换**，还有词汇差异。

### 词汇对照（高频）

| zh-Hans | zh-Hant | 备注 |
| --- | --- | --- |
| 相册 / 相簿 | 相簿 | 简中两个混用，繁中统一用「相簿」 |
| 视频 | 影片 | 简中「视频」→ 繁中「影片」 |
| 照片 | 照片 | 一致 |
| 删除 | 刪除 | 简单繁体字转换 |
| 保存 | 儲存 | **不是「保存」**，是「儲存」 |
| 设置 | 設定 | 简中「设置」→ 繁中「設定」 |
| 默认 | 預設 | 简中「默认」→ 繁中「預設」 |
| 信息 | 訊息 | 通讯类「信息」→「訊息」 |
| 同步 | 同步 | 一致 |
| 退出 | 結束 / 退出 | App 内多用「結束」；本项目混用，看上下文 |
| 撤销 | 復原 | 简中「撤销」→ 繁中「復原」 |
| 提示 | 提示 | 一致 |
| 加载 | 載入 | 简中「加载」→ 繁中「載入」 |
| 数据 | 資料 | 简中「数据」→ 繁中「資料」 |
| 网络 | 網路 | 简中「网络」→ 繁中「網路」（注意：香港用「網絡」，台湾用「網路」，本项目以台湾用语为主） |
| 文件 | 檔案 | 简中「文件」→ 繁中「檔案」 |
| 备份 | 備份 | 简单转换 |
| 全选 | 全選 | 简单转换 |
| 取消全选 | 取消全選 | 简单转换 |
| 选中 | 選取 | 「选中」→「選取」更地道 |

### 标点

- 标点全角，同 zh-Hans。
- 问号用「？」，繁中标点风格和简中一致。

### 复数

同 zh-Hans，只写 `other`。

## ja（日本語）

### 风格

- **常体 vs 敬体**：App UI 一般用**敬体（〜です / 〜ます）**，但按钮和短标题用名词形/动名词。
  - 按钮：`削除`、`キャンセル`、`完了`（动名词，不带 する／します）
  - 说明：`現在のライブラリに写真がありません`（敬体）
  - 弹窗 message：`削除してもよろしいですか？`（敬体 + 问句）
- **不要过度敬语**：不要 `〜ていただけますでしょうか`、`〜お願い申し上げます`，App 不需要这么客气。中等礼貌的 `〜ですか？／〜ますか？` 足够。
- **不要用「お」「ご」乱加**：`お写真` `ご削除` 都不要，写 `写真` `削除` 就够。

### 标点

- **句末用「。」**（完整说明句末加句号）。但按钮、标题、提示**不加**。
  - 例：`現在のライブラリに写真がありません`（说明句不加句号，看现有文件惯例）
  - 例：`削除してもよろしいですか？`（问句用「？」）
- 用日文标点：`。、！？「」`，**不要**用 `.,!?"" `。
- 占位符前后**不留空格**：`%lld件の写真`（紧贴），和中英文风格不同。
- 数字用半角阿拉伯数字：`5件`，不要 `５件`。

### 词汇

- 「写真」= 照片，「アルバム」= 相册（片假名外来语）。
- 「動画」/「ビデオ」= 视频，本项目用「ビデオ」（看 `arrange.page.video_subtitle` = `ビデオファイルを整理します`）。
- 「削除」= 删除，「キャンセル」= 取消，「確認」= 确认，「完了」= 完成，「続ける」= 继续。
- 「ライブラリ」= 相册库/照片库，对应 iOS 系统词汇。

### 复数

只写 `other`。日文也不区分复数。文案用「N件」、「N枚」、「N個」配合量词。

## ko (한국어)

### 风格

- **礼貌级别**：App UI 通常用 **합쇼체（〜습니다 / 〜ㅂ니다）** 中等礼貌。
  - 完整句：`사진 %lld장이 삭제 표시되어 있습니다`、`완료되지 않은 정리 작업이 있습니다`
  - 问句：`계속하시겠습니까?`
  - 按钮：用名词或动名词，**不带 〜습니다**：`삭제`、`취소`、`완료`、`확인`、`계속`
- **不要用 해요체（〜요）**：太亲切，不符合 App UI 中性风格。
- **不要用 해체（반말）**：太随便。
- 例外：iOS 系统按钮风格里少数动作短文案可以用 `〜기` 形式：`나가기`、`선택 항목 삭제` —— 本项目混用，看现有惯例。

### 标点

- **完整句末加「.」或不加都行**，看现有文件惯例，多数**不加**（按钮、标题、提示都不加）。
- 问句末加「?」（半角）。
- 用半角标点：`,.?!"`，韩文标点其实和英文一样用半角。
- 占位符前后**不留空格**：`사진 %lld장` —— 数字和量词紧贴。
- 数字用半角阿拉伯数字。

### 词汇

- 「사진」= 照片，「앨범」= 相册（아) 「앨범」是英文 album 的外来语写法）。
- 「동영상」/「비디오」= 视频，本项目用「동영상」（看 `arrange.page.video_subtitle` = `동영상 파일을 정리합니다`）。
- 「삭제」= 删除，「취소」= 取消，「확인」= 确认，「완료」= 完成，「계속」= 继续。
- 「보관함」= 库/收纳所，对应 iOS 「Library」。本项目 `arrange.home.empty_title` = `보관함이 비어 있습니다`。
- 量词常用：`장`（张，用于照片）、`개`（个，通用）、`건`（件，少用）、`명`（名/人）。

### 复数

只写 `other`。韩文不区分复数。

## 翻译时的自检 checklist

每条翻译写完后过一遍：

- [ ] 占位符个数、类型和源一致（`%lld` 没变 `%d`，`%@` 没漏）
- [ ] 长度没失控（按钮没翻成长句）
- [ ] 大小写符合该语言惯例（en 是 Title Case 还是 Sentence case）
- [ ] 标点符合该语言惯例（中日韩用全角/半角各自正确）
- [ ] 没用过度敬语 / 过度随便的语体
- [ ] 没踩本项目术语雷区（视频 vs 影片、设置 vs 設定、相册 vs 相簿）
- [ ] 复数条目英语 one/other 文案不同，中日韩只有 other

## 参考已有翻译

xcstrings 文件里已经有大量翻译过的条目（很多带 `REVIEWED` state 的）。**翻译新条目前如果不确定风格，先 grep 一下相似语义的已有条目**，参考它的翻译方式。例如要翻译「找到 N 个空相簿」，可以参考 `empty_albums.found_count_format` 已有翻译。这样能保持术语和风格一致。

```bash
# 在 xcstrings 里找语义相近的已有 key
grep -n "REVIEWED" Photos/Resources/Localizable.xcstrings | grep -i "delete\|删除"
```
